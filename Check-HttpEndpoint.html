📄 Check-HttpEndpoint.ps1 – Script Documentation

Purpose

This PowerShell script tests an HTTP or HTTPS endpoint (such as an Autodiscover service) and performs two types of analysis:

  1. Raw HTTP Capture
    • Connects directly to the server using TCP (and SSL for HTTPS).
    • Sends a manual GET request.
    • Captures the exact raw HTTP response (headers + body) as sent by the server.
    • Saves this to a log file (HttpAnalysis.txt) in the same folder as the script.
    • Detects the server type from the Server: header if present.
  2. Parsed HTTP Request
    • Uses Invoke-WebRequest to fetch the same URL.
    • Displays HTTP status code, response time, and parsed headers.
    • Detects server type from parsed headers.
    • Optionally saves the full body to a file.
    • Displays the first 40 lines of the body in the console.
    • Performs basic content analysis (HTML, XML, other, or empty).

How It Works

  1. Raw Capture First
    • The script calls Get-RawHttpResponse before anything else.
    • This ensures the log file is always written, even if the parsed request fails.
    • The log file path is set to: 
      $PSScriptRoot\HttpAnalysis.txt
      This means it will be saved in the same folder as the script.
  2. Server Detection
    • Both raw and parsed responses are scanned for a Server: header.
    • If found, the script identifies common server types (Varnish, Apache, Nginx, or other).
  3. Parsed Request
    • The script uses Invoke-WebRequest to get a structured response.
    • Displays headers, status code, and response time.
    • Shows the first 40 lines of the body in the console.
    • Performs a simple content-type check.
  4. Error Handling
    • If the parsed request fails, the script attempts to extract the status code, headers, and body from the error response.
    • All exceptions are caught and displayed with elapsed time.

Parameters

- TestUrl          (Required)  The full URL to test.
- SaveBodyPath     (Optional)  Path to save the full response body.
- AnalysisFilePath (Optional)  Path to save the raw HTTP log file.
                               Defaults to "$PSScriptRoot\HttpAnalysis.txt".

Usage Examples

Example 1 – Basic Test

PS C:\Scripts> .\Check-HttpEndpoint.ps1 -TestUrl "https://example.com/autodiscover/autodiscover.xml"

Captures raw HTTP response and saves it to HttpAnalysis.txt in the script folder. Displays parsed request results in the console.

Example 2 – Save Full Body

PS C:\Scripts> .\Check-HttpEndpoint.ps1 -TestUrl "https://example.com/test" -SaveBodyPath "C:\Temp\fullbody.txt"

Saves the full parsed response body to C:\Temp\fullbody.txt. Still writes raw HTTP response to HttpAnalysis.txt.

Example 3 – Custom Log File Path

PS C:\Scripts> .\Check-HttpEndpoint.ps1 -TestUrl "https://example.com" -AnalysisFilePath "C:\Logs\RawHttp.txt"

Saves raw HTTP response to C:\Logs\RawHttp.txt instead of the default location.

Output Files

  • HttpAnalysis.txt → Raw HTTP headers + body exactly as sent by the server.
  • (Optional) Full body file if -SaveBodyPath is specified.

Notes

  • The raw capture uses a manual TCP/SSL connection, so it will show exactly what the server sends — even if Invoke-WebRequest fails or strips headers.
  • The parsed request may differ from the raw capture because PowerShell’s web client automatically follows redirects, handles cookies, and may normalize headers.
  • If you get "No Server header found", the server is deliberately hiding its type.
