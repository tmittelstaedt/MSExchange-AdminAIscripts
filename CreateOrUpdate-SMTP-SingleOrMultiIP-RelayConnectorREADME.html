Exchange Receive Connector Creation/Update Script

Version: 2.1
Author: Ted Mittelstaedt

📌 Purpose

This PowerShell script creates or updates a secure Exchange Receive Connector that allows anonymous SMTP relay from one or more specific internal hosts.

  • Prevent open relay
  • Allow only specified IP addresses to relay externally
  • Automatically apply the correct relay permissions
  • Work in both local and remote Exchange Management Shell

✨ Features

  1. Warning Message – Displays a clear warning about proper usage before running.
  2. User Input – Prompts for:
    • Connector name
    • One or more IP addresses (comma-separated)
    Uses the current server name automatically.
  3. DNS Validation – Checks PTR and forward DNS for each IP; stops if any fail.
  4. IP Conflict Check – Ensures no entered IP is already assigned to another connector.
  5. Connector Creation or Update – Updates or creates with correct settings.
  6. Relay Permissions – Grants NT AUTHORITY\ANONYMOUS LOGON the right Ms-Exch-SMTP-Accept-Any-Recipient.
  7. Remote Session Compatibility – Uses .Identity.ToString() for remote PowerShell.
  8. Verification – Confirms relay rights are applied.
  9. Summary Output – Displays connector details.

🛠 Requirements

  • Exchange Management Shell (local or remote)
  • Exchange Organization Administrator rights
  • PowerShell 5.1 or later
  • DNS PTR and forward records for each IP

🚀 Usage

Save the script as CreateOrUpdateReceiveConnector.ps1
Open Exchange Management Shell.
Run:
    .\CreateOrUpdateReceiveConnector.ps1
Follow the prompts.

💡 Example Run

Enter the name for the Receive Connector: RelayFromAppServer
Enter the internal host IP(s) allowed to relay (comma-separated if multiple): 192.168.1.50,192.168.1.51

📧 Example PowerShell Command to Test Relay

Send-MailMessage -From test@yourdomain.com -To recipient@externaldomain.com `
    -Subject "Relay Test" -Body "This is a test email" `
    -SmtpServer exchangeserver.yourdomain.local -Port 25

⚠ Notes

  • Safe for production use only if you enter trusted internal IP addresses.
  • Do NOT allow relay from 0.0.0.0/0 or public IP ranges.
  • Always verify relay functionality from allowed IPs after running.
