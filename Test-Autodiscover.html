Exchange Autodiscover Diagnostic and Protocol Detection Tool

Author: Ted Mittelstaedt, Portlandia IT LLC
Version: 1.0
Date: 08/10/2026

1. Purpose

This PowerShell script is designed to test and diagnose Microsoft Exchange Autodiscover endpoints. It performs DNS lookups, sends multiple Autodiscover POST requests, saves the returned XML responses, and detects whether the server advertises IMAP, Exchange ActiveSync (EAS), or both. It also provides a summary table and optional CSV export for reporting.

2. Features

  • Performs DNS lookups for A, AAAA, CNAME, and SRV records related to Autodiscover.
  • Tests multiple Autodiscover URLs:
    • https://<domain>/autodiscover/autodiscover.xml
    • https://autodiscover.<domain>/autodiscover/autodiscover.xml
  • Sends three types of Autodiscover POST requests:
    1. Desktop Outlook schema (full XML)
    2. “Mobile” Outlook schema (full XML)
    3. MobileSync schema (short XML, phone-style)
  • Saves all XML responses to disk if requested.
  • Scans all XML responses for IMAP and EAS/ActiveSync indicators.
  • Displays warnings if both IMAP and EAS are detected (mixed protocols).
  • Outputs a summary table and optionally exports it to CSV.

3. Logic Flow

  1. DNS Resolution
    • Queries DNS for A, AAAA, CNAME, and SRV records for the Autodiscover host.
    • Displays results and stores them for the summary.
  2. HTTP Autodiscover Tests
    • For each Autodiscover URL:
      • Sends a Desktop Outlook schema POST request.
      • Sends a “Mobile” Outlook schema POST request.
      • Sends a MobileSync schema POST request.
    • If credentials are not provided, falls back to a simple GET request.
  3. Saving XML Responses
    • If a save path is provided, writes each XML response to disk with descriptive filenames.
  4. Protocol Detection
    • Combines the content of all three XML responses.
    • Searches for the strings “IMAP” and “EAS” or “ActiveSync” (case-insensitive).
    • Logs results as:
      • IMAP DETECTED
      • EAS DETECTED
      • IMAP + EAS DETECTED
      • PASS (no IMAP/EAS found)
  5. Summary and Export
    • Displays a summary table of DNS and HTTP test results.
    • Optionally exports the summary to CSV.

4. Protocol Explanations

EWS – Exchange Web Services

  • A SOAP-based API provided by Microsoft Exchange.
  • Used by Outlook, third-party applications, and migration tools to access mailbox data, calendars, contacts, and tasks.
  • Typically accessed via HTTPS at /EWS/Exchange.asmx.
  • Supports advanced features like free/busy lookup, delegate access, and folder synchronization.

EAS – Exchange ActiveSync

  • A Microsoft protocol designed for mobile devices to synchronize email, calendar, contacts, and tasks.
  • Uses HTTP(S) and XML over a long-lived connection.
  • Commonly used by iOS Mail, Android Email, and Windows Mail apps.
  • Endpoint is usually /Microsoft-Server-ActiveSync.

IMAP – Internet Message Access Protocol

  • An open standard email retrieval protocol (RFC 3501).
  • Allows clients to access and manage email stored on a mail server.
  • Supports folder management and message flags but does not natively sync calendars or contacts.
  • Commonly used by non-Exchange servers (e.g., Dovecot, Courier, Gmail IMAP).

5. Autodiscover Beyond Outlook

While Autodiscover is a Microsoft technology primarily associated with Outlook, it can be implemented for other email clients. By setting up an Autodiscover server that returns XML in the expected format, non-Outlook clients can automatically configure their email settings.

Example: The open-source project autodiscover-email-settings provides a PHP-based Autodiscover service that can be used to supply configuration data for Thunderbird, Apple Mail, and other clients.

6. Usage

powershell.exe -ExecutionPolicy Bypass -File .\Test-Autodiscover.ps1 -Domain example.com -EmailAddress user@example.com -Credential (Get-Credential) -SaveXmlPath "C:\Temp\AutodiscoverResults"

7. Output Interpretation

  • PASS: Autodiscover returned valid XML without IMAP/EAS indicators.
  • EAS DETECTED: Exchange ActiveSync is advertised.
  • IMAP DETECTED: IMAP is advertised (may indicate non-Exchange server).
  • IMAP + EAS DETECTED: Both protocols are advertised (mixed environment).
  • ERROR: The request failed (network, authentication, or server error).

8. Notes

  • Mobile clients may fail if Autodiscover endpoints return HTTP errors other than 500 (e.g., 401, 403, 404).
  • Ensure that unused or misconfigured endpoints are removed from DNS or return a proper 500 error.
  • This script is intended for diagnostic purposes and should be run by administrators with appropriate permissions.
